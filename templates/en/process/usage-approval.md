## 1. Procedure overview

Follow this procedure when adopting a new open source component or changing the version of an existing one.

<!-- 5230 §3.1.5.1: a documented procedure for reviewing and recording license obligations, restrictions, and rights -->

```
Open source adoption request
    ↓
License check (compare against the allowlist)
    ↓
[Copyleft?] → legal review
    ↓
Vulnerability scan (check CVEs)
    ↓
[Critical/High CVE?] → look for an alternative or check for a patch
    ↓
Program Manager approval
    ↓
SBOM update
    ↓
Complete distribution-checklist.md before release
```

## 4. License obligation review

<!-- 5230 §3.1.5.1: review and record the obligations, restrictions, and rights of each identified license -->

| License type           | Distribution method   | Obligations                                        | How to fulfil them                         |
| ---------------------- | --------------------- | -------------------------------------------------- | ------------------------------------------ |
| MIT / Apache-2.0 / BSD | All distribution      | Copyright statement, license notice                | Include in the NOTICE file                 |
| LGPL                   | Embedded/distribution | Publish source code or guarantee dynamic linking   | Keep dynamic linking / publish source code |
| GPL-2.0 / GPL-3.0      | Embedded/distribution | Publish the full source code                       | Publish source code (when distributing)    |
| AGPL-3.0               | Including SaaS        | Publish source code including for network services | Publish source code                        |
| Not on the allowlist   | —                     | Prior legal review is mandatory                    |                                            |

## 5. Prior vulnerability check

<!-- 18974 §4.1.5.1, §4.3.2 -->

When adopting a new component:

- [ ] Look up CVEs for that version in the OSV API or NVD
- [ ] Confirm there are no Critical or High CVEs
- [ ] If a Critical or High CVE exists: move to a patched version or reconsider the adoption

## 6. SBOM update obligation
