## MCP 대응은 몇 단계인가

**단계가 아니다.** 사이트 문서(`ai-coding/agent-governance`)가 이렇게 정의한다.
"Rules(2단계)가 AI 가 무엇을 쓰는지를, CI 게이트(3단계)가 산출물을 통제한다면, 이 페이지는
남은 면을 다룬다 — 에이전트가 어떤 도구를 호출하고 어떤 입력을 읽는지."

즉 5단계는 **AI 가 만든 코드**의 통제 축이고, MCP 도구 거버넌스는 **에이전트가 호출하는 도구**의
통제 축이다. 서로 직교하며 어느 한쪽으로 대체되지 않는다. 2단계 절에서 "규칙 내재화와 함께 도구
측 통제도 필요하다"고 병행을 권한다.

슬라이드에는 제목 위 라벨로 표시한다. 10~12번은 `LEVEL 4 / 4A / 4B`, 13~14번은
`단계가 아닌 다른 축`이다. 라벨이 없으면 11번이 "Level 3 finds only what a rule describes" 로
시작해 3단계 이야기로 읽힌다.

## 결정 사항

- **영문 한 판본만 쓴다.** 발표는 한국어로 하고 슬라이드는 영문으로 둔다.
- **디자인** — 흰 배경(`#fbfbfa`), 검정 활자, 1px 규칙선, 브랜드 청색(`#1a5fd0`) 하나.
  카드 배경, 그라디언트, 태그 칩, 형광 강조를 쓰지 않는다. 강조는 색이 아니라 굵기로 한다.

- **밀도** — 슬라이드에는 3초 안에 읽히는 것만 둔다. 설명은 발표자 노트로 내린다.
- **발표자 노트는 한국어** — 발표를 한국어로 하기 때문이다. 영문판에도 한국어 노트를 넣는다.

## 연습용 출력본

`index.html?handout` 으로 열면 발표 연습용 인쇄물이 된다. A4 세로 한 장에 슬라이드 한 장을
줄여 얹고, 그 아래 말할 내용을 작은 글씨로 붙인다. 왼쪽 위에 슬라이드 번호, 오른쪽 위에
시작 시각과 길이가 나오므로 시간 배분을 보면서 연습할 수 있다. 대사는 `.notes-src` 를 그대로
읽어 오므로 원고를 두 벌 관리하지 않는다. `make-pdf.sh` 가 `handout.pdf` 로 뽑는다.

인쇄 레이아웃에서 걸렸던 것 세 가지를 적어 둔다.

- 슬라이드 축소에 `transform` 이 아니라 `zoom` 을 쓴다. `transform` 은 720px 레이아웃 박스를
  그대로 두기 때문에, 인쇄할 때 잘라 내는 영역이 페이지 아래끝까지 늘어난다.
- 슬라이드를 감싸는 상자에 테두리(`border`, `outline`)를 두르지 않는다. 높이를 고정해도
  Chrome 이 페이지 아래끝까지 그린다. 가로 규칙선 두 줄로 대신했다.
- `html` 과 `body` 배경을 흰색으로 맞춘다. 다르면 두 배경의 경계가 페이지마다 세로선으로
  찍힌다.

## 웹사이트 공개

슬라이드는 Trusted OSS 웹사이트의 레퍼런스 > "발표 자료"(영문 Talks) 에서 연다.
대메뉴로 올리지 않는다. 발표 기록은 레퍼런스 성격이라 그 아래가 맞다.

| 항목        | 경로                                                                       |
| ----------- | -------------------------------------------------------------------------- |
| 목록 페이지 | `website/reference/talks.md` (영문 i18n 사본 있음)                         |
| 슬라이드    | `website/static/reference/talks/oss-summit-korea-2026/slides.html`         |
| 공개 주소   | `/reference/talks` 및 `/reference/talks/oss-summit-korea-2026/slides.html` |
| 동기화      | `deck/publish.sh` 가 `deck/index.html` 을 static 으로 복사                 |

목록 페이지와 슬라이드는 주소가 이어져 보이지만 계통이 다르다. 앞은 Docusaurus 라우트라
`build/reference/talks.html` 로 나오고, 뒤는 `static/` 파일이라 `build/reference/talks/`
디렉토리로 복사된다. 파일과 디렉토리라 이름이 겹쳐도 부딪히지 않는다.

슬라이드를 고치면 `bash deck/publish.sh` 를 돌려야 공개본이 따라간다.

목록 페이지에서 슬라이드로 거는 링크는 `pathname:///reference/talks/...` 형식이어야 한다.
`static/` 파일은 Docusaurus 라우트가 아니라서 일반 링크로 적으면 빌드가 깨진 링크로 막는다.
사이트가 `trailingSlash: false` 라 목록 페이지는 `build/reference/talks.html` 로 나온다.
로컬에서 `python3 -m http.server` 로 확인할 때는 `.html` 을 붙여 열어야 한다.
